* 1.0 (Q1 2014) (first public release, Borja Sotomayor, University of Chicago)

(this repo's own git history only starts in 2015 -- see the gap above --
so 1.0's content here comes from the project's own later self-description,
docs/sigcse2016-chidb.pdf, cross-checked against what's actually in the
tree: source file copyright headers, include/chidb/chidb.h's API, and
Makefile.am's module list)

** btree
- table and index B-Trees over a page-based file format that is a strict
  subset of SQLite's own -- a chidb file opens directly in the real
  sqlite3 shell, though not the other way around (no overflow pages, a
  single 4-byte-int primary key only, a handful of column types)
- schema (tables + indexes) itself stored as a table B-Tree, rooted at
  page 1 of the file

** dbm
- a 37-opcode, register + cursor bytecode machine explicitly modeled on
  SQLite's VDBE (see docs/claude_notes/notes_sqlite.txt for specifics) --
  register manipulation, control flow, cursor open/seek/move, column/key
  access, record building, and B-Tree/index creation and insertion

** sql
- lexer/parser (src/libchisql/sql.l, sql.y), "the current incarnation of
  the SQL parser" per the SIGCSE paper's acknowledgments, credited there
  to Allen Nelson
- internal representation unified with relational-algebra notation (sigma,
  pi, rho) rather than an ad hoc AST -- the paper's own pedagogical
  selling point, "reinforcing in a working system what students have
  otherwise seen only on paper"

** api / shell
- chidb_open/prepare/step/finalize + column accessors, mirroring
  sqlite3's own C API almost exactly (include/chidb/chidb.h)
- interactive shell (src/shell/) with .parse/.opt/.dbmrun/EXPLAIN, for
  inspecting a query's parse tree, optimized tree, or compiled bytecode
  without a debugger

** released as
- a BSD-licensed assignment *framework*, not a finished product: what
  ships in the public distribution has btree.c/dbm-ops.c/optimizer.c's
  function bodies stripped down to "/* Your code goes here */" stubs for
  the four course assignments (B-Trees; Database Machine; Code
  Generation; Query Optimization) -- see the 2.0 entry above for what was
  *still* a stub in this fork, twelve years later
- at github.com/uchicago-cs/chidb, with the architecture/assignment docs
  at chi.cs.uchicago.edu/chidb (both cited in the SIGCSE paper; also see
  docs/claude_notes/notes_dbm_spec.txt and notes_file_format.txt, pulled
  from that site since it isn't shipped in this repo)
- assignment 1 (B-Trees) done in pairs; assignments 2-4 (DBM, Code
  Generation, Query Optimization) done in teams of four (SIGCSE paper
  section 3, "the most recent format we used")
- the DBM assignment's own shape changed over the years: "in the past,
  students had to implement the entire DBM from scratch themselves...
  we have since standardized the internal representation of the DBM" so
  graders could test against a fixed dbm.c/dbm-types.h -- exactly the
  split this fork's own dbm-ops.c-only implementation (2.0, above) still
  follows
- the authors' own stated future work (SIGCSE paper section 6), still
  true of this fork: no concurrency/locking/transactions attempted at
  all ("the biggest gap in chidb"); the query-optimization assignment
  considered the least satisfying of the four, since the supported SQL
  subset "only lend[s] itself to some limited optimizations" and
  optimizer output is hard to grade automatically; and a wish for a
  step-by-step DBM debugger that was never built

* Beta (2010-2014) (SQL front end, RA/SRA compiler design, further course iterations)

(no git history reaches this far back either; dated from source file
copyright headers -- "Copyright (c) 2009-2015" throughout src/libchidb/
-- and the SIGCSE paper's own account of this period)

- sql: Allen Nelson implements "the current incarnation" of the SQL
  lexer/parser (SIGCSE paper acknowledgments)
- codegen: the RA/SRA (sigma/pi/rho) internal representation takes shape
  as the code generator's target, tying the SQL compiler to relational-
  algebra theory
- taught across further iterations of the databases course, building
  toward the 1.0 public release above (SIGCSE paper: five iterations
  total between 2009 and 2015, enrollment ranging 6-62 students)
- shell: src/shell/ takes shape, still being refactored as late as
  mid-2014 (src/shell/commands.h: "Created on: Jul 31, 2014")

* Alpha (Q2 2009) (chidb created for CMSC 23500's first offering)

- architecture: the SQLite-inspired design is established from the
  start -- a page-based B-Tree file format (a subset of SQLite's own)
  underneath a VDBE-inspired database machine -- per include/chidb/
  chidb.h's own attribution ("2009, 2010 Borja Sotomayor ... Some
  modifications by CMSC 23500 class of Spring 2009")
- first taught in CMSC 23500 at the University of Chicago, Spring 2009;
  per the SIGCSE paper's acknowledgments, "our colleague Sharon Salveter
  ... taught the chidb course in its first two iterations, and so got
  the ball rolling with what was at the time untested work"
